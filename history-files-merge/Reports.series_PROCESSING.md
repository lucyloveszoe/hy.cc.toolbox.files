# txt.done 整理流程与规则（可复用）

目的：把论坛帖子（每篇一个故事）按**实际发生地点**归入 `locations/`，把成系列的帖子抽到 `series/`，并保证每个 `.txt` 都有一份准确的 `.manifest.csv`。

## 1. 目录与文件约定

```
txt.done/
  locations/   每个地点一个 XX.txt + XX.manifest.csv（川渝、江浙、广东、湖北、山西、青海 …）
  series/      每个系列一个 XX.txt + XX.manifest.csv
  <年份或来源目录>/  待处理的原始输入（处理完成后删除已入库的文件，只保留待定项）
```

### txt 格式
- 一个文件里放多篇故事，**篇与篇之间恰好空一行**，文件以换行结尾。
- 故事全文 = manifest 里 `start_line..end_line` 的行（含故事内部的空行），用 `'\n'.join(lines[s-1:e])`。
- 读写一律用 `encoding='utf-8'`；读时用 `utf-8-sig` 吃掉 BOM。

### manifest 格式（UTF-8 带 BOM，csv）
- **locations**：`no,file,start_line,end_line,chars`
  - `file` = 原标题 + `.txt`（标题里的 `/` 换成全角 `／`）
- **series**：`part,title,source_file,source_start_line,source_end_line,start_line,end_line,chars`
  - `source_*` 记录该篇**迁出时**在来源地点文件里的位置（迁出后即失效，仅作溯源）
- 通用规则：`no/part` 从 1 连续；`chars` = 故事全文字符数（`len('\n'.join(seg))`，不含篇间空行）；行号 1 起算。

## 2. 地点判断流程

1. **自动初筛**：对 标题 + `【买春地址/地点】` 字段 + 正文，用「地名关键词表」统计各地区命中次数。关键词表覆盖：
   川渝、广东、上海、山东、云南、湖南、安徽、江浙、湖北、京津、东北、俄罗斯、美国、其他海外，
   以及后来新增的 河北、福建、海南、江西、河南、陕西、山西、广西、贵州、新疆、甘肃、内蒙、宁夏、青海。
   （关键词表需随新地点扩充，格式 `{地区: [省名, 城市名, 区县/地标…]}`）
2. **标记疑点**：标题/地址命中的地区 ≠ 文件所在地区；或标题地址无命中且正文最高命中地区 ≠ 文件地区。
3. **人工读原文确认**（关键词只是线索，必须读上下文）。常见误报：
   - 「川沙」是上海地名，不是川渝；「天府丽」是成都水疗；「澳门路」是武汉的路；「玉林港式休闲」在成都；
   - 「南平」在重庆语境里多是「南坪」笔误；「美国中文在线论坛」只是帖子来源；
   - 小姐籍贯（四川妹、湖南人…）不代表发生地。
4. **辅助线索**：论坛评分行里的「XX军区总司令/副司令」是发帖版块（如「江苏军区」「湖北军区」「川渝军区」），可佐证地点；
   货币/地名/店名（新西兰币+Panmure → 奥克兰；芽笼 → 新加坡；「豫区」→ 河南）。
5. **归类原则**：按**故事实际发生地**，不按发帖版块、作者、小姐籍贯。
   - 行政区划为准：燕郊、保定、野三坡 → 河北；徐州/南通/常州等 → 江浙。
   - 没有对应文件的地点 → 新建 `XX.txt`（如 河北、福建、海南、江西、河南、陕西、山西、贵州、青海、宁夏）。
   - 实在无法判断 → 留在原处/放入待定，**由用户决定**，不要猜。
6. 用户确认过的归类（不再复查）：川渝《狂日傲慢的女行政主管》《意外的勾兑》《白天鹅里寻找的插曲》、上海《炮打丹叶大波妹》（南瑞路）、江浙《红星路红星加油站对面》。

## 3. 去重规则

- 精确重复：对文本去掉所有空白后取 md5，跨 locations + series 比对。
- 近似重复：标题核心相同 + `difflib.SequenceMatcher` 比对正文（取 `[100:700]` 片段，ratio > 0.8 视为重复）。
- 处理：重复篇**不追加**（或删掉较晚/较短的一份）；保留带作者标签、较完整的版本。
- 追加前必须与目标库对比，追加后再全库查一遍重复。

## 4. 追加（append）算法

对目标 `XX.txt`：
1. `old = 读取并 rstrip('\n')`；`n = old.count('\n') + 1`；新篇起始行 `ln = n + 2`（中间一个空行）。
2. 每追加一篇：写 `'\n' + 全文 + '\n'`；manifest 记 `(k, file, ln, ln+len(seg)-1, len(全文))`；然后 `ln += len(seg) + 1`。
3. 文件不存在则新建：首篇 `ln = 1`，无前导空行。
4. 追加用的 manifest 序号接着已有最大序号往下排。

## 5. 删除/迁出后重算 manifest（必须重建，不能只删行）

1. 读原 txt 的行与 manifest；保留需要的篇。
2. 逐篇从原行区间取 seg，重新排：篇间插一个空行，重算 `start/end/chars`，序号重新 1..N。
3. 写回 txt + manifest。若一个文件被删空，则同时删除其 txt 和 manifest。
4. 用「原 manifest 的行号」定位要删的篇——**每次删除前重新读 manifest，不要沿用旧序号**（删一篇后后面的序号都变了）。

## 6. 系列（series）提取规则

- 判定：同一系列标题/编号（（上）（中）（下）、之一/之二、第N篇/季、系列名一致），数量 **≥3 篇**（用户要求过的例外：2 篇的「援交系列小T感受」「苏狼在川木桶浴系列」也保留）。
- 也包括跨地点的同作者连载（如作者 blade99 的「鄂狼99系列」，散在湖南/江西/江浙/川渝/上海）。
- 不算系列：仅作者相同或主题相似、没有编号（德阳红宇、黄龙溪等）——但用户点名要提取的照提（德阳红宇系列、成都黄龙溪系列、川沙系列、天府丽西安姐妹花系列、山东家政系列）。
- 提取步骤：按系列内顺序（一二三/上中下）取出各篇 → 写入 `series/名称.txt` 与 manifest（记录 `source_file` 与来源行号）→ 从 locations 对应文件删除并按第 5 节重建 manifest。
- 系列内重复篇删掉，保留带作者标签/较完整的那份；`part` 重新从 1 编号。
- 系列名跟随内容范围（如 济南家政系列 并入威海、青岛后改名「山东家政系列」）。

## 7. 乱码修复（文件名与首行）

- 症状：GBK 字节被当作 西里尔(iso8859-5) 或 泰文(cp874) 解码成 UTF-8 文件名/首行。
- 修复：`乱码.encode('iso8859-5' 或 'cp874').decode('gbk')`；macOS 文件名可能是 NFD，先 `unicodedata.normalize('NFC', …)`。
- 同时修文件名和文件第一行（标题行），保持两者一致；若标题被截断，以正文里的完整标题为准。
- 只对确认乱码的文件操作（别用「含西里尔/泰文字符」一刀切，真实俄文文件名会被误伤）。

## 8. 验证清单（每次改动后必跑）

对 locations 与 series 的每个 manifest：
- `no/part` 从 1 连续；`end_line >= start_line`；
- `len('\n'.join(lines[s-1:e])) == chars`；
- 所有非空行都被某条 manifest 覆盖（无遗漏内容）；
- 全库无重复篇（空白归一后 md5）；
- 标题与故事首行一致（不一致的单独列出人工看）；
- 再跑一遍地名关键词扫描，确认只剩已知误报。

## 9. 安全习惯

- 任何改写/删除前，先把相关文件备份到 scratchpad 目录（`bak*/`）。
- 追加、迁移之前先出方案（分类表、重复清单、待定项）让用户确认；删除源文件需用户明确同意。
- 输入目录里用户可能手工改过文件：**读最新内容，别信旧 manifest**（曾发生 pending.txt 被改后行号全部失效，已用备份还原并重切）。
- 地点无法判断的故事不要猜，放入待定并询问用户。

## 10. 坑与细节

- Python 以文本模式读文件会把 `\r\n` 转成 `\n`；所有读写保持同一方式，行号才一致。
- 追加时 `rstrip('\n')` 后再补 `'\n\n'`，保证篇间只有一个空行。
- 输入 manifest 列名可能是 `title`（旧）或 `file`（新）；series 用 `title`。
- 文件名中的 `/` 要替换，避免路径问题。
- 外围脚本用 `python3 -I`（隔离模式），处理不受信输入目录时不要在该目录里运行解释器。

## 12. HTML 报告 + 图片的整理流程（`data.done`：`*_Report` 目录，2026-11-17）

适用对象：`<来源>/reports/<folder>/*.html`、`<来源>/images/<folder>/p<NNN>_*`、`<folder>_summary.csv`、`<folder>_images_manifest.csv`。与第 1–11 节（txt 入库）是两套流程，别混用。

### 12.1 目录与不变式（任何改动后都必须成立）

```
data.done/
  <来源>_Report/
    reports/<folder>/…html        报告（图片用相对路径链接）
    images/<folder>/p<NNN>_…      只放被某个报告引用的图片
    <folder>_summary.csv          每个源页面一行
    <folder>_images_manifest.csv  每个源文件一行
  Reports.series/html/<系列>/…html + images/…   按系列归并后的报告（图片放同级 images/）
  Reports.series/txt/…                          txt 入库（第 1–11 节）
```

1. 每个 `<img>` 本地链接都能解析到真实文件（0 断链）。
2. 每张图片至少被一个 html 引用（0 孤图）。
3. summary/manifest 里每个非空 `output` 都指向现存文件；每个 html/图片恰好被列一次。
4. 文件名里的 `p<NNN>_` 是页面序号，**同一张图出现在多个页面会有多份不同名的字节相同副本**——这是流水线本身的结果，不是错误。

### 12.2 查重（先扫描、只出清单、不动文件）

- **图片**：对所有文件做 `md5`，字节相同才算重复；每组按「路径最短、再按字典序」保留第一个。
- **HTML 不能直接比字节**：报告里的图片链接含 `p<NNN>_`，同一帖的两份保存页也必然字节不同（0 组）。要比较**规范化内容**：去掉 `<head>`、`<h1>` 标题（标题可能被截断，如 `…MM[34P` vs `…MM[34P]`）、所有标签、全部空白，再加上「去掉 `p<NNN>_` 前缀后的图片名序列」。
  - 文字+图片序列都相同 = 完全重复（可移走一份）。
  - 文字相同、图片数不同 = **近似重复，不要自动处理**（多半是一份缺图），单独列出交用户看。
- 报告里引用了该图片 ≠ 该图片可以删：**先查谁引用**（`grep -F <文件名>` 或解析 `<img src>`）。

### 12.3 移走/合并时不弄断链接（核心规则）

1. 先备份，再动手；删除一律改成「移到 tmp 目录并保留相对结构 + 写 `DUPLICATES_MAP.tsv`（移走的文件→保留的原件）」。**不要边移边改，先出方案**（本次先移了图片，造成 894 个断链，用户要求整体还原，教训见 12.8）。
2. 移动某批报告时：
   - 解析这些报告的 `<img src>`（`html.unescape` 后相对报告目录求路径）。
   - 检查：图片是否被**其他**报告引用（共享则复制或停止，别移）；目标目录是否已有同名文件（不同内容则改名，不可覆盖）；报告文件名是否与目标重名（重名保留两份，新的加后缀，如 ` (2009_02_03_maichun)`）。
   - 移动图片到目标 `images/`，改写报告里的 `src`（目标布局：同级 `images/<name>`；`&` 写回 `&amp;`），写新 html、删旧 html。
   - 立刻全库复扫（见 12.6）。
3. 报告所在目录变了，图片相对路径要重新算；`reports/russian → reports/mcjt` 这类同来源内的移动，图片随之移到 `images/mcjt/`，链接用 `../../images/mcjt/`。

### 12.4 summary / manifest 的更新

- `output` 一律是**相对于该 CSV 所在目录**的路径（例：`reports/wet/x.html`、`../Reports.series/html/上海狼在俄罗斯/x.html`）。
- 只有 `wet_summary.csv` 原本有 `output` 列；其余 summary 缺这一列，需新增：html 页 = `reports/<folder>/<页面去掉.htm>.html`，txt 页/unsupported 页若文件不在 `data.done` 则留空。
- 定位移动后的文件：按文件名在 `Reports.series/html/…` 与原目录内查找，**必须唯一**；重名时（含加后缀的）按来源批次区分，不要把两份指到同一个文件（本次 `maichun_summary` 的六十七/六十八曾误指到 MCJT 那份，靠「listed twice」检查发现）。
- 文件已不在 `data.done`（`images.only/…`、合并 txt）的行：`output` 置空，manifest 的 `status` 追加 ` [output file no longer in data.done]`，不删行、不改其它列。
- 磁盘上有图但 manifest 没有（如同图被多页引用留下的 `p029_md_…`、`p123_f6c6…`）：补一行 `source_file = <源页面干名>_files/<原文件名>`，`status = copied: used by a saved post`，`output` 为现路径；源页面从引用它的报告对应的 summary 行取。
- 读写 CSV：`utf-8-sig`（带 BOM）读，写回同样带 BOM，保持原换行（`\r\n` 或 `\n`），列顺序不变，只用 `csv` 模块。
- `<来源>.Single/images/*/manifest.csv`（列 `image,original_url`）是另一种清单，不参与上面的核对，别改。

### 12.5 按名称归并成系列（例：`狼在俄罗斯` → `Reports.series/html/上海狼在俄罗斯`）

1. 范围 = 指定的各来源目录；先扫**文件名、`<title>`、正文**三种命中，分别统计（本次只有文件名命中）。
2. 用户给的路径可能带 shell 转义（`\[` `\(` `\ ` `\#`），要还原成真实文件名。
3. 对命中的全部报告按 12.3 移动，目标内：`<系列>/<报告>.html` + `<系列>/images/<图片>`。
4. 更新 CSV（12.4），再全库复扫。

### 12.6 验证清单（每步之后都跑，输出计数）

- html 数、图片数；本地 `<img>` 断链数 = 0（`src` 先 `html.unescape`；跳过 `http:`/`data:`）。
- 未被任何 html 引用的图片数 = 0。
- 所有 CSV 的非空 `output` 都存在；`output` 无重复指向；html/图片都被列一次（`.Single` 除外）。
- 复跑 md5 查重，对照基线（本批：676 组 / 875 份多余图片；html 完全重复 37 组 / 41 份）。

### 12.8 本次教训

- **用户说「移走重复项」时，先确认这些重复项是否仍被报告引用。** 图片字节相同≠可以直接移走；移走会让引用它的 html 全部断图。先决定「改链接到保留件」还是「把报告也一并处理」，并让用户确认。
- 误操作后的还原：移走时保存 `DUPLICATES_MAP.tsv`，改写前把 html 备份到 `html_backup_before_relink/`；还原顺序 = 先用备份覆盖被改写的 html，再按映射表移回 html，最后移回图片；还原后用文件数和 md5 重复组数核对与初始一致（6,836 个文件 / 676 组 / 875 份）。
- 备份目录放 scratchpad 或 `data.done` 之外，别放进被扫描的目录里，否则会被当成重复/孤图。
- 用户会在两轮之间自行调整目录（本次把 `Reports.series/上海狼在俄罗斯` 挪成 `Reports.series/html/上海狼在俄罗斯`，并新增 `txt/`）：**每轮开始先重新扫描现状，不要沿用上一轮记下的路径。**
- 脚本一律 `python3 -I` 运行，放在 scratchpad，不在数据目录里执行；`find … -exec md5 -r` 的结果文件也放 scratchpad。
